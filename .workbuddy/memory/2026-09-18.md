## 手绘风格图标库调研（资料沉淀，未落地代码）

结论写入 `docs/图标与音效资源选型.md` §2.5「专题 · 手绘 / 涂鸦风格」。

关键事实：
- **手绘生态稀缺**：Iconify 237 个集合中，按 hand/sketch/doodle/scribble/ink/freehand 等检索仅命中 3 个，其中 `dinkie-icons` 经核查是等宽/几何字形集、非手绘，实际真手绘仅 `streamline-freehand`（1000，CC BY 4.0 需署名 Streamline）与其彩色版。
- **与 Lucide 同构（迁移成本最低）**：`@sketchyicons/react`（0.5.0，MIT，1756）实测 kebab 模块名与 Lucide 一一对应、PascalCase 导出 2004 个，props 与 Lucide 一致 → 现有 `icons-map-lucide.tsx` 换包名即可，仅缺 github/twitter。`scribbles-icons`（1.0.1，ISC，1744×3 权重）为 Lucide 重绘可变宽墨迹，fill 型、256 viewBox。
- **涂鸦卡通（需另建映射）**：`@oreo-design/doodle-icons`（MIT，152，48 网格，含 BoilFilter 沸腾抖动与逐笔绘制动效）；`react-doodle-icons`（MIT，439，源自 Khushmeen Sidhu 的 CC0 素材）。
- **引擎路线**：`roughjs`（MIT，<9kB）可把任意 SVG path 渲染为手绘线条，一套代码覆盖全部 62 语义、无映射缺口，代价是需自写适配层且形状展开为多条 path 节点。
- **落地风险**：手绘线条在 15px 以下易糊（sketchyicons 官方建议 <20px 保持 strokeWidth 2），本应用侧边栏/工具栏图标多在 14–18px，须先小尺寸实测；与现有 10 套库混用会明显不一致，宜作整套切换项。

## 三个新候选站点实测（写入选型文档 §2.7）

同名语义覆盖率按项目现有 62 个 IconName 比对。关键事实：
- **RuneIcons**（github.com/Nexvyn/runeicons）：LICENSE 实测为 **Apache-2.0**。宣传「900+ icons × 5 styles」不实——manifest 显示五风格各自 124–217 条（normal 217/duotone 213/fill 124/pixelated 215/glass 135），**glass 是与前四风格无关的另一套**。对 62 语义：normal·duotone·pixelated 各 35/62，fill 22/62，glass 仅 7/62。无 npm 包（`runeicons`、`@runeicons/react` 均不存在），需从仓库取 SVG 自建组件与映射。
- **Pixel Icon Library**（HackerNoon）：`@hackernoon/pixel-icon-library` 1.1.0 MIT，解包 579 SVG = regular 248 + solid 248 + **brands 59** + purcats 23，另含 PNG 与图标字体；**无 main/exports、无 React 组件**。主集与已用 `pixelarticons` 风格重复；独有价值是 brands 含 github/x/twitter/rss/podcasts。regular 约 52/62（含近义命名）。
- **Its Hover**：263 个 registry 条目（README 称 186+），**LICENSE 文件为 Apache-2.0**，但 README 的 Features 段写 "MIT licensed" —— **仓库自身表述矛盾**，署名时须按 Apache-2.0。经 shadcn registry 分发、依赖 `motion`，需开发期把源码落入仓库方能离线；约 40/62，缺 folder/close/plus/tag，不宜作主图标库，适合启动页/空状态等局部微交互。

结论：三家均不足以作为第 11 套完整主题（覆盖率不足 + 风格重复）；性价比排序为 PIL brands > Its Hover 局部补充 > RuneIcons glass 装饰性使用。
